# FastBF Project Layout

The current source tree is split by lifecycle:

- `caponlib/`: Python package and runtime pipeline.
- `native/`: CUDA native backend.
- `example/`: self-contained synthetic SAC smoke example.
- `configs/`: reusable configuration examples.
- `docs/USAGE_GUARDRAILS.md`: short forget-proof usage checklist.
- `tools/`: helper scripts for plotting and post-processing.

Concrete science-analysis projects are outside this source tree. The current
local handoff target is:

```text
C:\Users\admin\Desktop\FastBF_science_analysis
```

Local `testing/` directories are intentionally ignored. They are author-side
real-data regression/performance sandboxes, not release contents.

Local server notes and validation workspaces such as `server_beamforming/`,
`vpn108_server/`, `station_subarrays_7/`, and `exp_algorithm_validation/`
should live outside the repository. They are ignored if copied back into the
tree.

`native/fastbf_native`, `native/fastbf_native_power`, `bin/fastbf_native`,
`bin/fastbf_native_power`, and matching `caponlib/bin/<platform>/...` staged
binaries are generated by the native build/staging flow. They are intentionally
ignored by git and can be recreated with `make build`.

Windows support is currently retired while FastBF is being refactored. Do not
reintroduce `.pyd`/`.dll` build products or MSVC-specific paths until the
Linux/WSL pipeline is stable.

The installer auto-detects visible NVIDIA GPU architectures with `nvidia-smi`.
`FASTBF_CUDA_ARCH` or `python install_fastbf.py --arch ...` is only needed when
building for a different machine or when no GPU is visible during compilation.

The main user entry points are:

- `fastbf guide`
- `fastbf doctor CONFIG.ini`
- `fastbf inventory CONFIG.ini`
- `fastbf prepare CONFIG.ini`
- `fastbf checkmem CONFIG.ini`
- `fastbf run CONFIG.ini`
- `python install_fastbf.py`

The build flow is intentionally small:

- `make install` delegates the full user install to `install_fastbf.py`
- `make build` builds/stages native binaries without pip installing
- `make smoke` runs the self-contained example doctor/prepare/dry-run check
- `make clean` removes local build artifacts

`fastbf inventory` and `fastbf prepare` intentionally borrow only the outer
workspace discipline from FastXC. The lightweight FastBF workspace contains:

- `config.snapshot.ini`
- `nsl_catalog.tsv`, the lightweight NSL catalog for the workspace
- `saclist/*.tsv`, one timestamp-named SAC table per runnable timestamp
- `native/`, for native geometry and SAC-list manifests
- `bf/`, for native beamforming matrix outputs
- `log/` and `progress/`

`nsl_catalog.tsv` assigns deterministic 4-digit `nsl_id` values from sorted
`network`, `station`, and `location` keys. Empty SAC location ids are normalized
to `00`. The timestamp TSV columns are `timestamp`, `nsl_id`, `network`,
`station`, `location`, `component`, `sac_path`, and `array`. FastBF no longer
writes prepare/inventory/run meta JSON or FastXC-style manifest indexes.

The SAC scanner now follows FastXC's small-module split:

- `patterns.py` compiles root-relative SAC filename patterns and timestamp fields.
- `files.py` matches and filters files under each array root.
- `arrays.py` groups matched files by timestamp.
- `source_scanner.py` adapts those pieces back to FastBF's SAC-list table shape.

FastBF does not create FastXC middle-stage structures such as `path_plan/`,
`spack_by_timestamp/`, `xcache/`, `sourcepack/`, or `stack/`. The old Python
`SeisHandler`, `sac_refactor.py`, and `cfk`/`ias_capon` execution path have
been removed from the main tree; use the `legacy/pre-v2606` branch or the
`legacy-pre-v2606` tag when an old implementation is needed for comparison.
